# DeepViewer 0.8.0

Source version for the DSH 0.2.1-rc.5 kernel upgrade. Not signed, not notarized, and not published. There is no Git tag, GitHub Release, or installer asset for 0.8.0. The published installer remains [0.7.3 / Build 93](v0.7.3.md).

`buildNumber` stays 93 in this commit. `package-native.mjs` increments it by 1 when a real package is built, so the first packaging run from this source is expected to write Build 94. Prior release commits recorded the number only after that increment (0.7.3's build source commit carries 93, which is the number that was packaged). This record does not claim that Build 94 exists.

## Kernel

DeepSeek Harness moves from `0.2.1-rc.2` / `687f282e8625c6b8d11ff58211a90524be2e4317` to `0.2.1-rc.5` / `b830ec950faba0a46dda564be3e2d854afed94f1` (tag `dsh-v0.2.1-rc.5`) through [DV-0037](../specs/DV-0037-dsh-021-rc5/spec.md). CI checks out that commit.

rc.3 through rc.5, as described by the upstream release notes:

- rc.3 adds More menus in the sidebar, session view, and right panel, so entries can be pinned or hidden. It adds `@deepseek-ai/dsh-client-ui-entry-customization`, registered in the web-app patch as `entry-customization`. It fixes a New Session draft being dropped. The DeepSeek API key adapter follows the official `/models` list.
- rc.4 stops writing ACP diagnostics to stdout. The MCP client returns an empty resource list when the server does not declare the resources capability. It also fixes a view-tab tooltip.
- rc.5 lets the web UI render custom reasoning blocks. The `conversation.chat.reasoning.body` slot gains `rawText` on owner props, and `text` is the display text.

Upstream did not mark a breaking change for this rc line. The reasoning-body props note applies to custom reasoning renderers. DeepViewer does not render that slot.

## DSH-to-Figma

DeepViewer 0.8.0 bundles DSH to Figma 0.3.1, a GitHub prerelease whose peer range includes 0.2.1-rc.5. It is not an npm package. The signed tag `v0.3.1` points to `baa6054e73490afeba775328a248bb5bc0da8586`. [DSH to Figma 0.3.1](https://github.com/Duoasa/DSH-to-Figma/releases/tag/v0.3.1).

The core-only build now stages successfully: `Staged native dsh-to-figma@0.3.1 with pinned Harness peers`.

Installed DeepViewer uses port 3065. The dev build uses port 3066. 3055 in upstream docs is only the generic template default. Import the manifest generated under `DSH_HOME/figma`.

Users who already imported the old companion into Figma Desktop need to re-import it once to get featureVersion 3.
