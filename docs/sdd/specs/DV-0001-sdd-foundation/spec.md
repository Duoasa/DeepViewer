# DV-0001：SDD 文档系统基础

## 摘要

为 DeepViewer 建立仓库内、Markdown 格式、可由人和编码 Agent 共同执行的规格驱动开发体系。

## 背景与问题

项目当前只有品牌说明和许可证，尚无产品边界、架构基线、功能规格格式或验收记录。DeepViewer 计划基于快速变化的 DeepSeek Harness 定制 UI 和功能，如果没有稳定的决策与追踪体系，后续实现容易偏离目标并增加上游同步成本。

## 目标

- G-001：建立从产品目标到验证证据的统一目录和流程。
- G-002：让后续 Agent 在编码前能发现并遵守活动规格。
- G-003：提供足够具体、但适合早期项目的轻量模板。

## 非目标

- NG-001：本规格不选择桌面技术栈或上游接入方式。
- NG-002：本规格不建立自动化文档站点或 CI 门禁。
- NG-003：本规格不导入 DeepSeek Harness 源码。

## 功能需求

- R-001：仓库必须提供 SDD 总入口、治理规则、产品基线和架构基线。
- R-002：每个功能规格必须具有需求、设计、任务和验证四类文档模板。
- R-003：模板必须支持稳定 ID，并能从需求追踪到验收证据。
- R-004：根目录 Agent 指令必须把非平凡变更路由到 SDD 流程。
- R-005：项目 README 必须提供 SDD 入口。

## 非功能需求

- NFR-001：所有内部 Markdown 相对链接必须指向存在的文件或目录。
- NFR-002：体系不得预先锁定未批准的桌面框架或上游集成机制。
- NFR-003：文档必须明确独立品牌、上游许可和敏感数据边界。

## 验收条件

- AC-001：从根 README 可以导航到 SDD 入口，并继续访问治理、产品、架构、ADR 和规格模板。
- AC-002：复制 `_template` 后能获得 `spec.md`、`design.md`、`tasks.md` 和 `verification.md` 四个完整文件。
- AC-003：需求、验收条件、任务和验证表均定义稳定编号与映射规则。
- AC-004：根 `AGENTS.md` 要求非平凡实现只在规格批准后开始，并要求同步验证证据。
- AC-005：仓库包含一个填写完成的首个规格，用于证明体系可自举。

## 边界与失败行为

- 小型机械修改可以豁免新规格，但不能让现有文档失真。
- 实施中发生实质范围变化时，规格返回 `Review`。
- 链接或模板缺失视为系统不完整，不能进入 `Verified`。

## 数据、安全与隐私

本规格只创建项目文档，不处理运行时用户数据。模板明确禁止保存凭据、私有提示词和不必要的用户数据。

## 风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 模板过重 | 开发者绕过 SDD | 只保留支持决策和验收的必需章节 |
| 文档与实现漂移 | 规格失去可信度 | 完成定义要求同一变更更新文档与证据 |
| 与上游文档冲突 | 导入源码时增加合并成本 | SDD 集中在独立目录，根指令保持简洁并可合并 |
