# DV-0004：macOS 一体化标题栏

## 摘要

把 DeepViewer macOS 主窗口从带独立系统标题栏的默认窗口，改为内容延伸到标题栏区域的一体化窗口。原生红黄绿窗口按钮保留并位于应用左侧栏顶部；侧栏切换按钮位于交通灯右侧，收起后整栏消失而不是保留缩略轨道；整个主界面在顶部统一预留安全区，所有页面内容、按钮和 shell overlay 从安全区下方开始；除交互控件外的整个窗口顶部都可拖动。窗口与侧栏行为整体参考 Codex，现有 Harness 页面、窗口生命周期和安全边界保持不变。

## 背景与问题

DV-0003 的预览版使用 Electron 默认 macOS 标题栏。用户截图显示该标题栏以独立横条占据窗口顶部，并重复展示 `DeepSeek Harness` 标题，与应用内容形成明显分层。目标参考截图中的 Codex 使用内容延伸式标题栏：系统窗口按钮仍为 macOS 原生控件，但落在应用自身的侧栏/顶部区域内。

## 目标

- G-001：移除主窗口中独立、带标题文字的系统标题栏视觉层。
- G-002：保留 macOS 原生红黄绿按钮及正常的窗口移动、最小化、缩放和全屏行为。
- G-003：让窗口内容安全避让原生按钮，不遮挡 Harness 的主要交互。
- G-004：让侧栏收起、展开入口和顶部拖动行为与 Codex 一致。

## 非目标

- NG-001：不在本规格中重做 Harness 的会话页、品牌、主题或信息架构；只改变桌面窗口外壳与侧栏显隐方式。
- NG-002：不手绘或用 Web 控件替换 macOS 原生红黄绿按钮。
- NG-003：不改变 Windows 窗口外壳；Windows 仍由后续独立规格处理。

## 用户与用例

### UC-001：使用一体化 macOS 主窗口

- 参与者：macOS DeepViewer 用户。
- 前置条件：用户启动与 CPU 架构匹配的 DeepViewer 应用。
- 主流程：窗口显示现有 Harness surface；红黄绿按钮位于应用内容顶部区域；侧栏切换按钮位于交通灯右侧；窗口中不再出现独立标题文字横条；用户可整栏收起/展开侧栏，并可从顶部非交互区域移动窗口、最小化、缩放和进入全屏。
- 失败/退出流程：若平台不支持该窗口样式，构建或测试应失败，而不是隐藏系统按钮或退化成无法移动的无框窗口。

## 功能需求

- R-001：macOS 主窗口必须使用内容延伸式标题栏，不得显示独立的系统标题文字横条。
- R-002：窗口必须保留原生红黄绿按钮及其系统语义，不得以 Renderer 控件模拟。
- R-003：原生按钮必须位于应用左上内容区域，且与 Harness 的品牌、侧栏按钮和可点击内容保持非重叠安全区。
- R-004：用户必须可通过除按钮和可点击控件外的整个顶部区域移动窗口，并继续使用最小化、缩放和全屏行为。
- R-005：启动、失败和 Harness Web surface 三类页面必须使用一致的窗口外壳。
- R-006：侧栏的收起状态必须把整栏宽度降为零，不得保留图标缩略轨道；展开必须恢复先前的完整侧栏宽度和内容。
- R-007：侧栏收起/展开按钮必须位于原生交通灯右侧，并在两种侧栏状态下持续可见、可点击和可键盘操作。
- R-008：桌面壳必须复用 Harness 已有的侧栏状态与切换语义，不得创建与页面状态分离的第二套持久化状态。
- R-009：进入 macOS 原生全屏、交通灯自动隐藏时，固定侧栏按钮必须自动补位到窗口最左侧；退出全屏后必须回到交通灯右侧。
- R-010：桌面壳必须在主界面全宽预留统一的 48px 顶部安全区；侧栏、主栏、详情栏和 shell overlay 的页面内容都必须从安全区下方开始，且该约束在侧栏展开、侧栏收起和原生全屏状态保持一致。

## 非功能需求

- NFR-001：实现必须位于 DeepViewer Electron 主进程/桌面注入边界，不得在被忽略的上游参考 checkout 中形成唯一实现。
- NFR-002：不得扩大 Renderer 的 Node、IPC、导航或文件系统权限。
- NFR-003：窗口外壳配置必须有自动化断言；最终视觉与交互必须按 SDD 验证职责由维护者在 Apple Silicon 真机手动验收。

## 验收条件

- AC-001：Given ARM64 DeepViewer 主窗口，When Harness surface 已加载，Then 窗口顶部不显示独立标题文字横条，内容延伸到窗口顶部。
- AC-002：Given 一体化窗口，When 用户观察和操作左上角，Then 原生红黄绿按钮可见、没有被页面内容遮挡，并可执行关闭、最小化和全屏。
- AC-003：Given 一体化窗口，When 用户拖动预留的顶部安全区，Then 窗口可以移动，且 Harness 的常用按钮和输入仍可点击。
- AC-004：Given 启动页、失败页或 Harness surface，When 页面之间切换，Then 三者保持相同的标题栏形态且不闪回默认系统标题栏。
- AC-005：Given 自动化检查，When 校验 BrowserWindow 配置，Then macOS 使用 `hiddenInset` 原生标题栏样式、安全的交通灯位置和现有受限 `webPreferences`。
- AC-006：Given 侧栏已展开，When 用户点击交通灯右侧的侧栏按钮，Then 整个侧栏滑出且主内容扩展到窗口左边缘，不显示 56px 缩略轨道；再次点击后恢复完整侧栏。
- AC-007：Given 侧栏展开或收起，When 用户观察窗口左上角，Then 同一个侧栏切换按钮始终位于交通灯右侧且不会随侧栏内容消失。
- AC-008：Given 页面顶部存在切换按钮或其他可点击控件，When 用户拖动顶部其余区域或点击控件，Then 非交互顶部区域可移动窗口，控件仍正常响应且不会触发拖动。
- AC-009：Given 普通窗口中的侧栏按钮位于交通灯右侧，When 用户进入原生全屏，Then 按钮在交通灯隐藏后移动到左侧 16px；When 用户退出全屏，Then 按钮恢复普通窗口位置。
- AC-010：Given 侧栏已展开，When 会话页面显示顶部操作区，Then 左侧内容、主栏页签、右侧 `Session log` 均位于 48px 安全区下方，按钮可点击且不被拖动层截获。
- AC-011：Given 侧栏已收起，When 主栏扩展到窗口左边缘，Then 主栏标题和页签仍从 48px 安全区下方开始，不与交通灯或侧栏按钮重叠。
- AC-012：Given 应用进入 macOS 原生全屏，When 交通灯隐藏且侧栏按钮补位，Then 48px 全宽安全区继续存在，按钮补位不遮挡主栏内容。

## 边界与失败行为

- 全屏模式下遵循 macOS 对交通灯和系统菜单栏的原生显示/隐藏规则。
- 全屏补位必须由 Electron 原生全屏事件驱动，不得通过窗口尺寸或屏幕坐标猜测。
- 顶部安全区是桌面壳对 Harness 三列布局及 overlay 的统一约束，不得依赖会话页内单个按钮或页面专有选择器。
- 页面顶部的可点击内容不得被透明拖动区覆盖；桌面工具条中的交互控件必须声明为非拖动区。
- 未来 Windows 适配不得复用 macOS 专有的交通灯坐标。

## UX 说明

- 目标参考为用户提供的 Codex 截图：原生交通灯落在左侧栏顶部，窗口内容与边框构成单一表面。
- Codex 对齐还包括：面板切换按钮紧邻交通灯右侧、收起时整栏宽度为零、顶部非交互区域均可拖动。
- 顶部 48px 只承载原生交通灯、固定侧栏按钮和窗口拖动；Harness 页面内容从其下方开始。
- 不显示 `DeepSeek Harness` 系统标题文字；文档标题仍可由网页用于辅助功能和系统窗口识别。
- 使用原生按钮，不复制按钮颜色、hover 或按压动画。

## 风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 交通灯覆盖 Harness 侧栏顶部控件 | 品牌或折叠按钮不可见/不可点 | 预留 macOS 顶部安全区并做实机截图检查 |
| 无框区域不可拖动 | 窗口体验退化 | 保留原生 hidden title bar 行为；必要时仅在非交互区域定义 drag region |
| 页面跳转后桌面样式丢失 | 启动页和 Harness surface 不一致 | 窗口级配置作为权威，页面级安全区在每次导航后应用 |
| Harness 更新后内部 CSS 类变化 | 桌面工具条无法定位侧栏 | 从插件拥有的稳定样式标签发现当前模块类，并在找不到时保持页面可用、记录验证失败 |
| 拖动层覆盖网页按钮 | 顶部控件不可点击 | 工具条按钮使用 `no-drag`，顶部拖动层只承担非交互区域 |
| 页面或插件新增顶部按钮 | 新控件再次落入拖动层或交通灯区域 | 对三列容器和 shell overlay 统一应用安全区，不逐个匹配页面按钮 |
| 跨平台配置泄漏 | 未来 Windows 行为异常 | macOS 专有配置集中在窗口平台选项函数中 |
