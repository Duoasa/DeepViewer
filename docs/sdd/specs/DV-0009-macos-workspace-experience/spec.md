# DV-0009：macOS 工作区体验精修

## 摘要

把 DeepViewer 主窗口收束为清晰的“左侧栏 + 右侧 Chat”两列结构，并统一新会话欢迎页、
输入框定位、会话统计、侧栏品牌、原生材质与窗口控件在浅色、深色、聚焦和失焦状态下的表现。
本规格记录 `v0.1.2` 候选版本中已经完成并由维护者逐轮验收的工作区体验。

## 背景与问题

`v0.1.1` 建立了 macOS 一体化标题栏和顶部安全区，但快速迭代中暴露出全宽顶栏造成三段式
视觉结构、输入框随模型状态上下移动、欢迎内容相对剩余空间而非 Chat 画布居中、侧栏材质
断层、浅色原生控件可读性不足等问题。维护者要求从页面结构和状态约束本身解决这些问题，
而不是用覆盖色隐藏布局缺陷。

## 目标

- G-001：保持主窗口只有侧栏和 Chat 两列，系统安全区属于各自列的内部结构。
- G-002：所有会话状态共享稳定的输入框底边位置和模型统计位置。
- G-003：新会话欢迎内容、品牌和侧栏材质在浅色、深色、聚焦与失焦状态下保持一致。
- G-004：DeepViewer 对上游 UI 的定制具有受控、可同步和可测试的源码入口。

## 非目标

- NG-001：不改变 Harness agent loop、模型调用或会话数据格式。
- NG-002：不重做上游页面的信息架构、消息内容或设置界面。
- NG-003：不在本规格中执行签名、公证、DMG 上传或 GitHub Release 发布。
- NG-004：不替代 DV-0006 对启动页减少动态效果和 Runtime 失败态的剩余验收。

## 用户与用例

### UC-001：创建新会话

- 参与者：macOS 用户。
- 前置条件：DeepViewer 已进入工作区且没有当前消息。
- 主流程：用户看到 Chat 画布中心的欢迎内容，并在距离窗口底部固定位置的输入框开始任务。
- 失败/退出流程：页面尺寸或语言变化时，欢迎内容和输入框仍保持各自定位语义。

### UC-002：持续对话

- 参与者：macOS 用户、模型 Runtime。
- 前置条件：会话可以处于空闲、思考、流式输出或完成状态。
- 主流程：输入框底边不因状态或统计信息出现而移动；完成后的模型统计显示在 Chat 顶部安全区。
- 失败/退出流程：统计信息不存在时保留安全区结构，但不生成占位文案。

### UC-003：使用侧栏和窗口控件

- 参与者：macOS 用户。
- 前置条件：窗口可处于浅色/深色、聚焦/失焦、侧栏展开/收起或原生全屏状态。
- 主流程：侧栏展开时显示主题适配材质；失焦时使用稳定纯色；红绿灯和侧栏按钮清晰且位置稳定。
- 失败/退出流程：侧栏收起后 Chat 占满剩余宽度；全屏隐藏红绿灯时按钮按既有规则补位。

## 功能需求

- R-001：系统必须把侧栏、Chat 和可选详情区的安全区放在对应列内部，不得建立跨越整个窗口的
  独立顶栏；红绿灯和侧栏按钮必须位于侧栏安全区。
- R-002：系统必须把模型使用统计居中显示在 Chat 顶部安全区，并从输入框下方移除该统计，
  使内容出现或消失不改变输入框布局。
- R-003：新会话、思考、输出和完成状态的输入框必须共享距离窗口底部 `32px` 的基准位置。
- R-004：新会话必须在完整 Chat 画布中心显示 `48px`、整体 `50%` 透明度的 DeepViewer 图形，
  复用启动页的输入光标闪烁语义；下方 `40px` 显示随系统语言变化的“让我们做点什么”或
  `What shall we build?`。
- R-005：侧栏品牌必须使用受控 React 内联 DeepViewer SVG，默认高度 `20px`、保持
  `623:127` 比例、跟随当前文字颜色、无阴影且不可点击。
- R-006：macOS 窗口聚焦时，展开侧栏必须呈现单层原生半透明材质；窗口失焦时必须回退到
  主题匹配的纯色填充。项目列表底部淡出遮罩不得产生额外色彩断层。
- R-007：侧栏展开/收起过程中，切换按钮必须固定在正常窗口的 `left: 88px; top: 13px`，
  不得出现横向跳动；原生全屏状态继续使用既有左移规则。
- R-008：应用主题变化必须通过枚举受限的 Renderer-to-main 通道同步给 Electron 原生主题，
  使浅色和深色模式的红绿灯及原生材质保持可读。
- R-009：所有上游 UI 定制必须保存在 DeepViewer 跟踪源码中，由同步脚本确定性写入并重建
  固定 Harness checkout，不得只存在于被忽略的上游目录。

## 非功能需求

- NFR-001：保留 Electron `contextIsolation`、sandbox、导航限制和最小 preload bridge；主题通道
  只接受 `light`、`dark`、`system`。
- NFR-002：定制不得引入新的运行时第三方依赖，构建和同步失败必须以非零状态停止。
- NFR-003：欢迎动画必须只改变合成友好的视觉属性，并尊重系统减少动态效果设置。
- NFR-004：所有颜色和遮罩必须同时覆盖浅色、深色以及聚焦/失焦组合，不以单一背景截图为基准。

## 验收条件

- AC-001：Given 侧栏展开，When 检查窗口结构，Then 只有侧栏与 Chat 两个主视觉列，安全区
  分别属于对应列且不存在跨列顶栏。
- AC-002：Given 会话依次处于新建、思考和完成状态，When 比较输入框，Then 底边位置保持
  `32px` 基准不变，模型统计只在 Chat 顶部安全区显示。
- AC-003：Given 新会话，When 页面完成加载，Then 欢迎图形和本地化文案以完整 Chat 画布为
  基准居中，并符合尺寸、透明度、间距和光标动画要求。
- AC-004：Given 浅色或深色主题，When 查看侧栏品牌，Then SVG 跟随前景色、无阴影、不可点击
  且保持指定尺寸比例。
- AC-005：Given 窗口在聚焦与失焦之间切换，When 查看展开侧栏和列表底部，Then 分别呈现
  连续的原生材质与纯色填充，淡出遮罩没有可见色块边界。
- AC-006：Given 侧栏展开，When 反复收起和展开，Then 按钮在正常窗口中不横向跳动；进入
  原生全屏后仍按既有规则补位。
- AC-007：Given 应用切换浅色和深色主题，When 查看 macOS 原生窗口控件，Then 红绿灯与材质
  可读，且主题 IPC 不接受枚举外的值。
- AC-008：Given 全新或已固定的上游 checkout，When 执行覆盖同步与 build，Then 所有上述 UI
  定制可从 DeepViewer 跟踪源码确定性恢复，并通过相关类型和单元测试。

## 边界与失败行为

- 上游目标文件、锚点或预期替换次数不匹配时，同步脚本必须停止并报告具体覆盖项。
- 模型统计为空时不显示空字符串，但安全区结构继续承担窗口拖动和内容避让职责。
- 侧栏收起时原生材质列宽必须归零，不得留下透明窄栏或独立顶栏。
- 非 macOS 平台不启用原生 vibrancy、交通灯定位或主题同步注入。

## UX 说明

窗口视觉上始终是左右两列；安全区是列内空间，不是第三个导航层。输入框以新会话位置为所有
状态的统一基准。欢迎内容属于 Chat 画布而非输入框剩余空间。侧栏聚焦材质用于建立原生窗口
层次，失焦纯色用于减少背景干扰；浅色与深色模式必须具有相同的信息层级。

## 数据、安全与隐私

本规格不新增持久化用户数据或外部传输。主题桥只传递固定枚举，不传递设置对象、系统信息、
会话内容或凭据。会话统计仍来自现有页面状态，只改变显示位置。

## 风险

| 风险 | 影响 | 缓解方式 |
| --- | --- | --- |
| 上游 UI 结构变化 | 覆盖失效或写入错误位置 | 使用锚点、替换次数断言和自动测试，失败即停止 |
| 原生 vibrancy 与 Web 遮罩叠加 | 浅色或深色出现断层 | 单一原生材质层，遮罩使用透明度而非固定背景色 |
| 动态状态改变布局高度 | 输入框跳动 | 独立统计座位和统一 composer footer 高度 |
| 主题状态不同步 | 红绿灯或材质不可读 | 窄 IPC 同步 Electron `nativeTheme`，并验证枚举边界 |
