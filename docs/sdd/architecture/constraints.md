# 架构约束

## 已知约束

### C-001：上游许可证与归属

DeepSeek Harness 使用 MIT License。引入的上游文件必须保留版权和许可声明，第三方依赖继续遵守其各自许可证。

### C-002：独立品牌

DeepViewer 必须明确是独立社区项目。名称、界面和发布材料不得暗示获得 DeepSeek 官方背书。

### C-003：扩展点优先

产品定制优先放在插件、能力组合、应用层和 UI 适配器中。对上游核心的修改需要 ADR，说明为什么现有扩展点不足以及如何持续同步上游。

### C-004：敏感数据

凭据不得进入仓库、普通日志、规格示例或前端持久化。外部传输必须有明确目的、最小范围和用户可见控制。

### C-005：可恢复性

破坏性文件操作、持久化迁移、自动更新和任务取消必须定义失败语义及恢复路径。

### C-006：可访问性

主要工作流必须可使用键盘完成；状态不能仅依赖颜色表达；交互和布局需要支持缩放及合理的屏幕尺寸变化。

### C-007：可测试边界

运行时事件到 UI 状态的转换应可在无真实模型密钥的情况下测试。真实 API 测试补充关键集成，但不替代确定性测试。

## 待验证约束

- 首发操作系统和最低版本
- 安装包体积、冷启动和常驻内存目标
- 离线能力和网络代理要求
- 需要支持的 DeepSeek Harness 版本窗口
- 企业策略、团队共享和多用户边界

待验证约束在形成明确承诺前不得被当作已批准需求。
