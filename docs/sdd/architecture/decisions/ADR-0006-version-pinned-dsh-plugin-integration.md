# ADR-0006：固定版本并通过 DSH 扩展点集成第三方插件

## 背景

DeepViewer 需要接入第三方订阅模型提供方。插件同时包含 Node 能力与 Web 设置界面，并会处理
OAuth 凭据；直接复制源码会扩大长期分叉，运行时下载又会破坏可复现性与桌面签名边界。

## 决策

- 通过 DSH 官方 bundle patch 与 client manifest 扩展点加载插件，不修改上游 agent loop。
- 桌面清单与锁文件固定精确插件版本；构建时把插件写入版本化 Runtime，并记录插件元数据。
- DeepViewer 适配层只负责兼容校验、启动参数、本地化入口、安全边界、诊断和禁用开关。
- 插件缺失、版本不符或预检失败时不注入插件，内置 DSH 核心仍可启动。
- 不在已签名应用中下载或原地修改 `Contents/Resources/harness`。
- 默认不复制或长期维护第三方源码；确需分叉时另行评审范围、许可证和上游回合流策略。

## 后果

### 正面

- 插件更新成为显式、可审计的依赖变更，开发版与安装包行为一致。
- DeepViewer 保持与 DSH 扩展契约对齐，故障可以从核心启动路径隔离。
- 第三方许可证和版本信息可随 Runtime 一起审计。

### 代价与风险

- 插件内部的外部服务协议仍可能独立失效，需要兼容测试与可禁用路径。
- 当前插件只提供 owner-only 原子文件凭据存储。`v0.2.1` 公开预览版经维护者明确发布授权，
  批准隔离 DSH home 与 `0600` 权限作为该版本的临时等价方案；稳定版前仍须通过独立适配把
  长期令牌迁移到 macOS Keychain，或重新评审并批准安全边界。

## 备选方案

- 运行时从网络安装：拒绝，版本不可复现且会改变已签名资源。
- 直接完整分叉插件：暂不采用，维护与安全审计面过大。
- 把订阅协议重写进 DeepViewer：拒绝，重复实现且绕过 DSH 插件能力边界。

## 后续行动

- 由 DV-0011 实现首个固定版本插件、兼容验证、诊断与本地化设置入口。
- 稳定版前完成 Keychain 凭据适配；每次 DSH/插件升级继续执行第三方许可与兼容性审计。
