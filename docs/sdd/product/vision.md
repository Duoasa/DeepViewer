# 产品愿景

DeepViewer 是针对设计师优化的专用 Agent 工作台，连接设计探索、Figma 原生画布、素材处理与可运行原型。设计师可以委派任务、查看过程、干预关键步骤，并保留可编辑、可验证的交付物。此定位由维护者在 DV-0036 中明确提出；历史平台路线仍是方向，不代表已经交付。

## 目标用户

- 需要把需求、参考图转为可编辑设计与可运行原型的产品和交互设计师
- 希望用 Agent 处理 Figma 图层、组件、变量、素材和交付文档的设计师
- 希望在统一外壳中管理设计上下文、模型、工作流和权限策略的设计团队

## 核心问题

命令行 Agent 对复杂任务很强，但执行过程、上下文、权限和结果往往分散在终端输出中。直接修改底层 Harness 又会增加上游同步成本。DeepViewer 需要在保留 Harness 可组合能力的同时，提供清晰的可视化控制面。

## 产品承诺

- 用户能知道 Agent 当前在做什么、等待什么以及改变了什么。
- 高影响操作在执行前可被理解和控制。
- 会话、任务、工具事件和产物具有稳定的可追踪关系。
- UI 和工作流可以扩展，而不要求每次都修改核心 Agent 循环。
- 本地数据、凭据和外部传输范围对用户清晰可见。

## 当前目标

- 建立不依赖终端、Node 或包管理器的独立桌面体验
- 采用 macOS 优先、Windows 必须支持的双平台发行路线
- macOS 同时提供 Apple Silicon 与 Intel 架构产物
- 提供任务、会话、工具活动和文件变更的统一视图
- 复用 DeepSeek Harness 的插件化能力和运行时契约
- 为 UI、插件、模型提供方和权限流程建立清晰扩展点
- 建立可测试、可回滚、可持续跟进上游的开发方式

## 非目标

- 复制或冒充 DeepSeek 官方产品
- 通过 UI 暴露模型不可验证的隐藏思维链
- 在第一阶段替换 DeepSeek Harness 的核心 Agent 循环
- 默认把本地工作区、凭据或完整会话上传到云端
- 在缺少明确用例时同时支持所有模型和自动化平台

## 成功假设

以下内容目前是待验证假设，不是已承诺 KPI：

- 新用户可以在较少终端操作下完成首次 Agent 任务。
- 用户可以从界面定位失败步骤、权限等待和文件变更。
- DeepViewer 定制大部分通过插件或外围适配完成，上游同步保持可管理。
- 关键用户操作可由自动化测试和可重放事件覆盖。

## 开放问题

- DeepSeek Harness 采用 fork、subtree、vendor 还是依赖方式接入？
- macOS 首发支持的最低系统版本，以及稳定发行是否额外提供 Universal Build？
- Windows 首发支持的最低版本与安装器格式是什么？
- 哪些执行事件需要长期持久化，哪些只用于实时展示？
