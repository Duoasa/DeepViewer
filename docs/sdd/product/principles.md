# 产品与工程原则

## 1. 可观察，不伪造透明度

展示计划、工具调用、权限请求、进度、产物和错误等可验证事件；不把模型生成的解释包装成真实的隐藏思维链。

## 2. 用户始终拥有控制权

高影响操作需要明确的范围、目标和确认点。暂停、取消、重试和回滚应成为一等能力，而不是错误后的补丁。

## 3. 本地优先，外部传输显式

默认在本地保存工作区和会话数据。任何发往模型提供方或第三方工具的数据都应有可理解的来源和目的。

## 4. 插件优先于核心分叉

优先使用 DeepSeek Harness 的插件和能力扩展点。只有在扩展点无法表达稳定产品需求时，才考虑修改上游核心，并通过 ADR 记录原因和同步成本。

## 5. 上游可持续跟进

DeepViewer 的品牌、UI 和产品逻辑与上游来源保持清晰边界。保留许可证和通知，减少无必要的上游代码改写。

## 6. 可逆变更

持久化迁移、权限策略、自动更新和破坏性操作必须定义失败行为与回滚路径。优先选择能小步发布和验证的方案。

## 7. 证据决定完成

“代码已写”不是完成。用户可见行为必须由验收条件和可复现证据证明，关键路径应有自动化覆盖。

## 8. 无障碍与跨平台从设计开始

键盘操作、可读状态、缩放、对比度和平台差异在设计阶段评估，不作为发布后的修饰工作。
